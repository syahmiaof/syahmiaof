# Cursor effects and robot review

Implemented 1 October 2026 against the existing portfolio design.

## Delivered behavior

- Original Three.js robot replaces the hero compute core. The head and pupils follow the pointer independently; the body turns more gently. Hovering its region lifts the robot and opens one arm. Eyes blink occasionally.
- Portrait, project previews, Greetly cover and passport tilt with a pointer-positioned reflection. Large headings drift subtly and change to emerald. Primary, project and contact actions move magnetically while retaining their native links.
- Roadmap and lab rows draw an accent rule; capability and journey nodes enlarge on hover. Motion resets when the pointer leaves.
- Touch, reduced motion and unavailable WebGL retain a static robot illustration. Mobile copy does not ask visitors to move a cursor. The existing motion control disables the enhancements.
- Demand rendering stops after movement settles and outside the actual viewport. Visibility handling avoids continuing animation work in hidden tabs. No external model or new package was added.
- The existing layered intro remains. An early-load skip race was traced to the server-rendered button accepting clicks before hydration installed its handler. Skip now becomes enabled when modal handling is ready, with keyboard focus assigned after that state commits.

## Evidence

`tests/motion.spec.ts` checks rendered eye movement with image pixels, surface tilt/reset, magnetic actions, motion preference changes, the touch fallback and actual WebGL draw calls stopping offscreen. The early-skip and Escape focus cases also passed three repetitions each with two workers.

Desktop 1440×1000, laptop 1280×800 and mobile 390×844 captures are generated by `node scripts/capture-motion.mjs`. They include neutral/left/right robot poses and portrait/project hover states. See `QA.md` for the final combined regression result.

The final capture batch reported no browser runtime errors or horizontal overflow at all three sizes. Desktop robot tracking and mobile fallback/copy were visually confirmed. The final production suite passed all 39 tests; build and lint also passed.

Validation uses local Microsoft Edge and the production build. Physical mobile GPU behavior, Safari/Firefox and deployed performance remain unmeasured; the touch experience intentionally uses the lightweight static robot.

## Cinematic follow-up

The approved follow-up adds a GSAP robot entrance with camera movement and eye wake, improved model finishes and joints, and a scroll-controlled Greetly device breakdown. The diagram remains labelled as a schematic; its attendance record is illustrative. Direct stage selection and keyboard access survive reduced motion and small screens. Scene subscriptions keep geometry movement out of per-frame React renders; environment reflections are generated at 64px once per renderer.

`tests/cinematic.spec.ts` covers the robot entrance lifecycle, rendered device changes while pinned, event delivery and reverse selection, removing the pin through motion controls, and the mobile record. The first visual batch found missing title whitespace and a laptop note overlap; both were corrected together. Capture desktop/laptop/mobile states with `node scripts/capture-cinematic.mjs`.

Final confirmation: 43/43 tests passed in the combined production suite, full ESLint and production build passed, and all three capture sizes reported zero runtime errors and no horizontal overflow. The final laptop capture confirms separated layers, readable title spacing and a non-overlapping schematic note. The in-app preview was refreshed and the completed robot entrance state verified.
